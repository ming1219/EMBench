# EMBench：给 Agent 出题、阅卷的框架

**EMBench** 是一个框架，用来检验会调用工具的 Agent 有没有真正把任务做对。它的重点是**一套流程**，题目怎么写才能被验证、怎么自动判分、怎么保证判分本身可信。

现在的 Agent 会自己调用各种「工具」：查分子结构、预测密度、计算爆速、规划合成路线……
EMBench 检查这个过程做得对不对：

> 题目要求「先算氧平衡，再算爆轰参数」，AI 有没有选对工具？顺序对不对？
> 填进去的分子对不对？算出来的数字对不对？最后有没有把结论清楚地告诉你？

仓库里附带了一套从早期实验的**化学示例题**，用来完整演示这套流程（见[第 3 节](#3-示例题库)）。

## 1. 为什么做 EMBench

大模型正越来越多地以**智能体（agent）**的形式工作：一步步调用领域工具来完成任务。在科学计算领域，很难判断一个智能体是不是真的做对了——最终回答看起来合理，背后的工具调用却可能选错、漏做甚至编造。
EMBench 把这件事变成一个可度量、可复现、可迭代的工程问题：

1. **梳理典型任务，给出清晰规范。** 把真实的化学工作流——名称查结构、结构校验、性质预测、氧平衡与爆轰参数计算、分子生成、多步设计与筛选——整理成任务，每道题都有明确的任务描述、预期执行步骤和验证标准。
2. **可复现、可自动验证的运行环境。** 每道题是一个自包含的文件夹：指令、声明式判分规则、参考答案。判分离线运行、秒级完成、不需要调用模型，任何机器上结果都一致。
3. **可信的轨迹数据。** 智能体的执行过程被记录成标准化的工具调用轨迹（调用了什么工具、传了什么参数、得到什么结果、最后怎么回答），并按领域标准逐项验证：分子结构的规范写法、数值容差、前后步骤的一致性。
4. **有质量保证的任务数据。** 题库会自我检验：每道题的参考答案必须通过，空白、截断和已知错误的轨迹必须失败。有问题或判分过松的题目在影响结果之前就会被发现，保证题库的正确性与多样性。
5. **为模型评测和强化学习提供评估机制。** 通过与否的判定背后是多维度得分（工具选择、参数、数值结果、覆盖度、一致性、回答质量、效率），并支持多次重复试验的指标（pass@k、pass^k）。同一套判分器也可以直接作为强化学习环境的奖励信号。
6. **用失败分析驱动迭代。** 每道未通过的题都会指出具体是哪一项检查失败、为什么失败，便于分析失败案例、改进任务与环境、横向比较模型和智能体架构，并验证改动是否真正提升了能力。

## 2. EMBench 是怎么工作的

把它想成一场考试：

| 考试里的东西 | 在 EMBench 里是什么 | 在哪里 |
|---|---|---|
| 一道题 | 一个文件夹 | `embench/tasks/类别/题号/` |
| 题目 | 一段发给 AI 的中文指令 | 每道题文件夹里的 `instruction.md` |
| 阅卷标准 | 这道题要检查哪几项 | 每道题文件夹里的 `task.toml` |
| 标准答案 | 一份「满分答题卡」 | 每道题文件夹里的 `solution/trajectory.json` |
| 学生的答题卡 | AI 做题的全过程记录：调了哪些工具、填了什么、得到什么、最后说了什么 | 你自己准备（第 6 节） |
| 阅卷老师 | EMBench 程序 | `embench/` 文件夹 |
| 成绩单 | 一张表格：每类题答对多少、错在哪 | 每次阅卷后自动生成的 `report.md` |

**这套考卷本身也经过「验卷」**：每道题的标准答案必须拿满分；交白卷、少做一步、缺少判分所需的工具结果、或者犯典型错误（每道题都附带了错误示例），都必须判不及格。
这能发现有问题的题目，也能抓住这几类已知的错法。但它**不能保证所有错误答案都会被判错**：如果某道题的检查写得太松，验卷也发现不了。所以每道题都应该附带自己的错误示例。

## 3. 示例题库

这些题是从早期实验迁移过来的，用来演示框架怎么用，质量参差不齐。请把它们当作「怎么写题」的示例；自己出题见[第 9 节](#9-出一道新题)。

| 类别（文件夹名） | 题数 | 难度 | 这类题在考什么 |
|---|---:|---|---|
| `name2smiles` | 20 | 简单 | 给一个化学名称（如 TNT、CL-20），让 AI 查出它的结构式（SMILES，一种用一行字母表示分子结构的写法） |
| `smiles-validate-draw` | 10 | 简单 | 先检查结构式写得对不对，再画出分子结构图 |
| `smiles-to-3d` | 10 | 简单 | 把结构式变成三维的原子坐标 |
| `property-predict` | 10 | 中等 | 先检查结构式，再预测密度、爆速等性质 |
| `ob-kj` | 6 | 中等 | 先算氧平衡，再用 KJ 公式算爆速、爆压、爆温、爆容、爆热 |
| `generate-predict` | 10 | 中等 | 让 AI 设计若干个新分子，并预测指定的性质 |
| `magus-generate` | 2 | 中等 | 先确认晶体结构生成模块可用，再生成指定化学式的晶体结构 |
| `design-pipeline` | 3 | 困难 | 完整的分子设计流程：生成候选 → 预测性质 → 算爆轰参数 → 评估能不能合成 → 推荐最佳候选 |
| `design-multi` | 3 | 困难 | 带筛选条件的多目标设计，例如「在热分解温度高于 200℃ 的候选里，推荐爆速最高的」 |

想看某道题具体问了什么，打开对应文件夹里的 `instruction.md` 即可。例如 `embench/tasks/ob-kj/tnt/instruction.md`：

> 请计算以下分子的氧平衡值，并用 KJ 公式计算其爆轰参数（爆速、爆压、爆温、爆容、爆热）：Cc1c(cc(cc1[N+](=O)[O-])[N+](=O)[O-])[N+](=O)[O-]

## 4. 第一次上手（约 10 分钟）

下面以 Windows 为例，Mac / Linux 的步骤基本相同。**整个过程只需要复制粘贴命令，不需要写代码。**

### 第 1 步：安装 Python

Python 是运行 EMBench 的程序环境，需要 **3.11 或更新的版本**。

1. 打开 <https://www.python.org/downloads/>，下载最新版并运行安装程序
2. 安装界面最下方的 **「Add python.exe to PATH」一定要勾上**，然后点「Install Now」

> 已经装过 Python 的话，可以跳过这一步。检查方法见第 3 步。

### 第 2 步：下载 EMBench

1. 在本页面上方找到绿色的 **「Code」** 按钮 → 点 **「Download ZIP」**
2. 把下载的压缩包解压到任意位置，例如 `D:\EMBench`

### 第 3 步：打开「命令行」窗口

1. 用文件管理器打开解压后的文件夹（能看到 `README.md`、`embench` 这些文件的那一层）
2. 点一下窗口上方的**地址栏**，把里面的路径删掉，输入 `cmd`，按回车

会弹出一个黑色窗口，这就是命令行，而且已经自动「站」在 EMBench 文件夹里了。
先输入下面这行并回车，确认 Python 装好了：

```
python --version
```

看到类似 `Python 3.12.x` 就对了。如果提示「不是内部或外部命令」，请看[常见问题](#10-常见问题)。

### 第 4 步：安装依赖

EMBench 只需要一个额外的化学工具包 RDKit，用来识别「同一个分子的不同写法」。在命令行里输入：

```
pip install -r requirements.txt
```

国内网络较慢的话，可以改用清华镜像：

```
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

### 第 5 步：验卷（检查考卷本身没问题）

```
python -m embench check
```

几秒钟后，最后一行显示：

```
74/74 题通过自检
```

说明示例题库里的题全部通过验卷：标准答案都能拿满分，几类已知的错法（交白卷、少做一步、缺少证据、每道题自带的错误示例）都会被判错。

### 第 6 步：试着阅一次卷

先请两位「示范考生」：一位交标准答案，一位交白卷。

```
python -m embench run -a oracle --job 标准答案
python -m embench run -a nop --job 交白卷
```

第一位应该 100% 通过，第二位应该 0% 通过。成绩单会直接显示在窗口里，同时保存在
`embench\jobs\标准答案\report.md`，可以用记事本或任何 Markdown 阅读器打开。

## 5. 看懂成绩单

下面是用仓库自带的示例答题卡（第 6 节会用到）阅卷得到的成绩单：

```
**pass@1 = 33.3%**（Wilson 95% CI 6.1% – 79.2%，按 3 道题计）

| family      | 题数 | pass@1 | l1_tool | l2_args | l3_value | answer | efficiency | 调用数 | 冗余 |
| name2smiles | 2    | 50.0%  | 100.0%  | 100.0%  | —        | 50.0%  | 100.0%     | 1.0    | 0.0  |
| ob-kj       | 1    | 0.0%   | 0.0%    | 0.0%    | 50.0%    | —      | 100.0%     | 1.0    | 1.0  |

## 未通过（2）
- `name2smiles/rdx#0` — answer: 回答中未找到 1 个期望分子
- `ob-kj/tnt#0` — trajectory: calculateOxygenBalance: 未调用; ob_values: calculateOxygenBalance 未调用
```

逐项解释：

| 成绩单上的词 | 意思 |
|---|---|
| **pass@1** | **通过率**：每道题的所有必查项都对，才算这道题通过。33.3% 就是 3 道题过了 1 道 |
| **Wilson 95% CI** | **可信范围**。题少的时候分数会有偶然性：「6.1% – 79.2%」的意思是，换一批同类题再考，真实水平大概率落在这个区间。它**按题目数计算**：题越多区间越窄，但同一批题重复考多少遍都不会让它变窄 |
| family | 题目类别 |
| l1_tool | **选工具**：该用的工具用了没有，先后顺序对不对 |
| l2_args | **填参数**：交给工具的内容（分子、数量、选项）对不对 |
| l3_value | **算结果**：工具算出来的数值对不对 |
| coverage | **做完整**：设计类题里，每一个候选分子是不是都做完了全部分析 |
| consistency | **不编造**：后续分析的分子，是不是确实来自前面生成的结果，而不是凭空编出来的 |
| answer | **说清楚**：最后有没有把正确结论告诉用户 |
| efficiency | **不啰嗦**：有没有多调用不必要的工具（只作参考，不影响是否通过） |
| 调用数 / 冗余 | 平均每题调用了几次工具 / 其中多余的有几次 |
| — | 这类题不考这一项 |
| 未通过 | 列出每道没通过的题，以及具体错在哪一项 |

上面两道错题的原因，正好是两种典型错误：
- **`name2smiles/rdx`**：工具查对了，但最后只说了句「已经为您查询到 RDX 的结构」，**没把结构式告诉用户**
- **`ob-kj/tnt`**：题目要求先算氧平衡、再算爆轰参数，AI **跳过了氧平衡这一步**

**想比较多个 AI？** 把它们的成绩单目录一起交给 `report`，会得到一张并排对比的表：

```
python -m embench report embench\jobs\AI甲 embench\jobs\AI乙
```

**想看 AI 稳不稳定？** 同一道题让它做 3 遍（`-k 3`），成绩单会多出两个数：

| 指标 | 意思 |
|---|---|
| pass@3 | 3 次里**至少 1 次**做对的比例 —— 它「有没有能力」做对 |
| pass^3 | 3 次**全部**做对的比例 —— 它是不是「每次都靠谱」 |

## 6. 给你自己的 AI 阅卷

分三步：**让 AI 做题 → 把做题过程记成答题卡 → 交卷阅卷**。

### 6.1 让 AI 做题

把某道题的 `instruction.md` 内容原样发给你的 AI，让它正常调用工具完成任务。
（AI 需要能使用的工具清单见[第 8 节](#8-你的-ai-需要会用哪些工具)。）

### 6.2 写答题卡

答题卡是一个 `.json` 文本文件（可以用记事本编辑），记录 AI 做了什么。下面是仓库自带的示例
`examples/my_agent_outputs/name2smiles/tnt.json`：

```json
{
  "agent": {"name": "my-agent", "model": "my-llm"},
  "steps": [
    {
      "tool": "nameToSmiles",
      "args": {"name": "TNT"},
      "result": "{\"smiles\": \"Cc1c(cc(cc1[N+](=O)[O-])[N+](=O)[O-])[N+](=O)[O-]\", \"source\": \"builtin\"}"
    }
  ],
  "final_answer": "TNT（三硝基甲苯）的 SMILES 为 Cc1c([N+](=O)[O-])cc([N+](=O)[O-])cc1[N+](=O)[O-]"
}
```

| 字段 | 填什么 |
|---|---|
| `agent` | 给你的 AI 起个名字（会显示在成绩单上），`model` 可写所用的大模型 |
| `steps` | AI **按顺序**调用过的每一个工具，每次调用写一条 |
| └ `tool` | 工具名，必须和[第 8 节](#8-你的-ai-需要会用哪些工具)里的名字一致 |
| └ `args` | 交给工具的内容 |
| └ `result` | 工具返回的结果（原样复制即可）。**不要省略**：如果某项检查要靠它核对数值，缺了这一项这道题会判不通过（成绩单上显示「缺少证据」） |
| `final_answer` | AI 最后回复用户的完整文字 |

> 注意：上例中 AI 回答里的结构式写法和工具返回的不一样，但其实是同一个分子，**不会被判错**。

如果你的 AI 是用程序搭建的，让程序在做题时自动写出这种文件即可，不需要手抄。

### 6.3 交卷阅卷

答题卡要按题目的文件夹结构摆放：`答题卡目录/类别/题号.json`。例如：

```
examples/my_agent_outputs/
├── name2smiles/
│   ├── tnt.json      ← 对应题目 embench/tasks/name2smiles/tnt/
│   └── rdx.json      ← 对应题目 embench/tasks/name2smiles/rdx/
└── ob-kj/
    └── tnt.json      ← 对应题目 embench/tasks/ob-kj/tnt/
```

如果同一道题让 AI 做了好几遍（见下面的 `-k`），**每一遍单独一份答题卡**：`类别/题号/trial_0.json`、`trial_1.json`……一份 `题号.json` 只算一遍，不会被重复当成好几遍。

然后运行（`-t` 后面列出要阅哪几道题；不写 `-t` 就阅全部题目，没交答题卡的题按白卷处理）：

```
python -m embench run -a replay --replay-src examples/my_agent_outputs -t name2smiles/tnt name2smiles/rdx ob-kj/tnt --job 示例
```

就会得到[第 5 节](#5-看懂成绩单)那张成绩单。换成你自己的答题卡目录和名字即可：

```
python -m embench run -a replay --replay-src D:\我的答题卡 --job 我的AI第一次
```

**常用的选题方式**：

| 写法 | 意思 |
|---|---|
| `-t ob-kj` | 只阅 ob-kj 这一类 |
| `-t ob-kj name2smiles` | 阅这两类 |
| `-t "design-*"` | 阅所有以 design- 开头的类别 |
| `-t name2smiles/tnt` | 只阅一道题 |

想看全部题号：`python -m embench list`

## 7. 阅卷规则：怎样才算答对

每道题的 `task.toml` 里写明了要检查哪几项。**所有「必查项」都对，这道题才算通过**；
「参考项」（目前只有「不啰嗦」）只出分数，不影响通过。

阅卷时会做这些宽容处理，避免冤枉 AI：

| 情况 | 处理 |
|---|---|
| 同一个分子的结构式写法不同 | 视为相同（用 RDKit 识别） |
| 分子名写法不同，如 CL20 / CL-20 / cl_20 | 视为相同 |
| 列表顺序不同、大小写不同 | 视为相同 |
| 数值有很小的误差 | 允许（一般 1% 以内） |
| AI 多调用了几次无关的工具 | 不算错，只记入「冗余」 |
| 工具的可选参数（如图片尺寸）没按默认填 | 不检查 |

阅卷时**不会**放过的情况：

- 少做了题目要求的步骤，或者顺序颠倒
- 交给工具的分子、数量、选项填错
- 设计类题里，有候选分子没做完分析，或者分析的分子是编造的
- 最后没有把结论（结构式、推荐的候选）告诉用户。设计类题的回答必须**推荐一个确实生成过的候选分子**。只有推荐句里的分子才算数，前面顺带列举一个生成过的分子不起作用。暂缓（「建议暂缓选择，现有证据不足」）、拒绝推荐、只说「第一个」、或推荐了任何不在生成结果中的分子，都判错
- 缺少证据：某项检查需要的工具结果答题卡里没有，这道题判不通过，而不是跳过
- 伪造证据：值为 `null` 的工具结果、解析不了的分子都不算数。候选列表塞满 `null`、性质字段都在但值全是 `null`，这道题判不通过，并标记为证据不完整

## 8. 你的 AI 需要会用哪些工具

要参加这套考试，AI 需要能调用以下工具（名字要完全一致）：

| 工具名 | 作用 | 主要参数 | 用于哪类题 |
|---|---|---|---|
| `nameToSmiles` | 化学名 → 结构式 | `name` | name2smiles |
| `validateSmiles` | 检查结构式是否有效 | `smiles` | smiles-validate-draw、property-predict |
| `drawMolecule` | 画分子结构图 | `smiles` | smiles-validate-draw |
| `smilesTo3D` | 结构式 → 三维坐标 | `smiles` | smiles-to-3d |
| `batchPredictProperties` | 批量预测性质（密度、爆速、生成焓等） | `smiles_list`、`properties` | property-predict、设计类 |
| `calculateOxygenBalance` | 计算氧平衡 | `smiles_list` | ob-kj |
| `calculateKJ` | KJ 公式计算爆轰参数 | `smiles` | ob-kj、设计类 |
| `generateAndPredict` | 生成新分子（可同时预测性质） | `num`、`use_em`、`properties`、`skip_prediction` | generate-predict、设计类 |
| `predictRetrosynthesis` | 逆合成分析（评估能否合成） | `smiles`、`max_routes`、`time_limit` | 设计类 |
| `magusStatus` | 查看晶体结构生成模块是否可用 | 无 | magus-generate |
| `magusGenerate` | 生成晶体结构 | `formula`、`number` | magus-generate |

性质代号：`Density` 密度、`DetoD` 爆速、`DetoP` 爆压、`DetoQ` 爆热、`DetoT` 爆温、`DetoV` 爆容、`HOF_S` 固态生成焓、`Td` 热分解温度、`BDE` 键解离能。

> 这些工具的实现目前**没有**包含在本仓库中。你可以用自己的实现，只要工具名和参数一致即可；
> 想知道某个工具应该返回什么，可以参考对应题目 `solution/trajectory.json` 中的 `result`。

## 9. 出一道新题

1. 复制一个同类题目的文件夹，改个新名字，例如把 `embench/tasks/ob-kj/tnt` 复制成 `embench/tasks/ob-kj/my-molecule`
2. 修改里面的三个文件：
   - `instruction.md`：新的题目文字
   - `task.toml`：把 `id` 改成 `ob-kj/my-molecule`，再把要检查的分子、数值改掉
   - `solution/trajectory.json`：新题的标准答题卡
3. 验卷：`python -m embench check -t ob-kj/my-molecule`
4. 登记到题库目录：`python -m embench registry --write`

验卷不通过时，会用中文说明哪里有问题。比如标准答案拿不到满分、或者交白卷也能通过（说明检查项太松），都会报出来。

`task.toml` 能写哪些检查项、每项怎么配置，见 [docs/specification.zh-CN.md](docs/specification.zh-CN.md)。

## 10. 常见问题

**输入 `python` 提示「不是内部或外部命令」？**
安装 Python 时没勾选「Add python.exe to PATH」。重新运行安装程序，选「Modify」把它勾上；或者把命令里的 `python` 换成 `py` 试试。

**`pip install` 很慢或失败？**
使用第 4 节里的清华镜像命令。仍然失败的话，确认 Python 版本是 3.11 或更新。

**为什么一定要装 RDKit？**
同一个分子可以有很多种结构式写法。没有 RDKit，程序没法判断两种写法是不是同一个分子，正确的答案也可能被判错。

**成绩单里的中文是乱码？**
用支持 UTF-8 的编辑器（如 VS Code、Typora）打开 `report.md`，或者在命令行里先输入 `chcp 65001` 再运行命令。

**同一个 AI 每次做的结果不一样？**
很正常，大模型本身有随机性。让 AI 把每道题做 3 遍，每遍各存一份答题卡（`trial_0.json` … `trial_2.json`），用 `-k 3` 阅卷，看 pass^3（每次都做对的比例）就知道它稳不稳定。内置的两位示范考生（`oracle`、`nop`）每次答案都一样，所以不允许 `-k` 大于 1。

**改了阅卷规则，以前的成绩要重新考吗？**
不用。运行 `python -m embench score embench\jobs\某次成绩` 即可按新规则重新阅卷，答题卡还是原来那份。重判之前，这个 job 不允许续跑（哪怕只续跑没改过的题），以免一份成绩单里混着新旧两套规则判出的结果。

**阅卷中途断了怎么办？**
用同样的 `--job` 名字再运行一次，已经阅完的题会自动跳过，只阅剩下的。一个 job 只属于一个 AI：如果用已有的 job 名去阅**另一个** AI 的卷，EMBench 会直接拒绝，以免把两个 AI 的成绩混在一起。请换一个 `--job` 名字，或加 `--force` 清空这个 job 从头来。
